# Fate/Grand Index

A Fate/Grand Order index of every NA servant and Craft Essence (Past Chaldea), plus your own Spirit Origin List: roster, Guests, parties, rankings, versus, a summoning simulator, a materials planner, an NP damage calculator, a Story page, (0.27.0) a Servant Workshop for servants of your own and (0.50.0) a battle simulator and a Saint Graph maker. It ships as one self-contained HTML file that saves everything in your own browser, and (0.26.0) as a hosted site and installable app with accounts, sync and friends.

**Online: [fategrandindex.com](https://fategrandindex.com)** (the site and the installable app, with accounts and friends).

Status: **beta** (`0.50.0-beta`; alpha up to 0.28.1). Version 1.0.0 will be the full website and app.
[fategrandindex.com](https://fategrandindex.com) will usually be ahead of the app and offline HTML in releases.

## Layout

| Path | What it is |
|---|---|
| `dist/Fate_Grand_Index.html` | The built page, the file you open in a browser. Built from `src/`, never edited by hand. |
| `src/page.html` | The page itself; `@@styles@@` and `@@app@@` mark where the style sheets and the script go. |
| `src/styles/*.css` | The style sheets, joined in name order. |
| `src/app/*.js` | The script, joined in name order into one script (the files share one scope; they are parts, not separate modules). |
| `src/assets/` | Pictures that are built into the page (logo, class icons, card art, the skill icon sheet). |
| `src/data/atlas_data.js` | NA servant and Craft Essence data, generated by `tools/gen_atlas.py`. Don't edit it by hand. |
| `data/atlas/` | The Atlas Academy NA exports that `atlas_data.js` is made from (gzipped). |
| `tools/build.py` | Puts `src/` together into `dist/Fate_Grand_Index.html` and `site/`. |
| `site/` | The hosted site (built): the page as `index.html` with the app's manifest, service worker (`sw.js`), icons and `_headers`. Cloudflare Pages serves this folder. |
| `src/site/` | What `site/` is made from: `head.html` (added to the page's head), `sw.js`, `manifest.webmanifest`, `_headers`, the icons. |
| `functions/`, `server/` | The hosted site's `/api/` (Cloudflare Pages Functions): accounts, sync, pictures, friends. `server/app.js` lists every address. |
| `docs/hosting.md` | Putting the site online on Cloudflare, step by step. |
| `tools/dev/` | A local copy of Cloudflare (wrangler) for trying the hosted site: `serve.py`. |
| `tests/` | Browser tests (Playwright) and `tests/run.py` to run them; `tests/api/` tests the hosted site against a local Cloudflare. |
| `legacy/` | The old build (a 0.7.1 page plus patch scripts `patch_v8.py` … `patch_v21.py`), kept read-only for reference. `src/` was cut from its 0.19.0 output and rebuilds it byte for byte. |

## Building

Needs Python 3 (standard library only). Node is used for a syntax check when it is installed.

```sh
python3 tools/build.py           # writes dist/Fate_Grand_Index.html and build/seeded.html (sample roster, for tests)
python3 tools/build.py --check   # fails if dist/ is not what src/ builds
```

Commit `dist/Fate_Grand_Index.html` together with the `src/` change that produced it.

When the Atlas Academy data changes, replace the exports in `data/atlas/` and run:

```sh
python3 tools/gen_atlas.py       # rebuilds src/data/atlas_data.js
python3 tools/build.py
```

## Tests

```sh
pip install -r tests/requirements.txt && python3 -m playwright install chromium
python3 tests/run.py             # builds, then runs every suite (-j 2 runs two at a time)
python3 tests/run.py craft       # only suites whose name contains "craft"
python3 tests/run.py --ci-fonts  # with the fallback fonts GitHub's machines have (catches text that runs too wide)
```

The tests don't need the internet: most suites swap the pictures that would come from Atlas Academy for placeholders, and the sample roster in `tests/fixtures/sample-roster.json` is built into `build/seeded.html`. Screenshots go to `build/test-work/`.

The hosted site has its own tests, which need wrangler (`cd tools/dev && npm install`): `python3 tests/api/test_api.py` (the server; `--d1-pics` keeps pictures in the database) and `python3 tests/api/test_hosted_ui.py` (the site in a browser: sign-up, a second device, sync, combining rosters, friends, a shared link, offline) and `python3 tests/api/test_hosted_owner.py` (the owner and the servants coming to NA).

GitHub Actions runs the build check and every suite on each push to `main` and on every pull request, and the hosted site's tests as a second job (`.github/workflows/test.yml`).

## Live NA updates (0.21.0)

Home's "On NA now" block reads Atlas Academy's NA export files (`info.json`, `basic_servant.json`, `basic_equip.json`, `basic_event.json`, `nice_gacha.json`) straight from the browser: `info.json` at most every six hours while the page is open, the lists only when NA's data changed. A short summary is kept in `localStorage` under `spirit-origin-list:v1:live`. The code is in `src/app/24-live-na.js`. Since 0.24.0 the block shows the login bonuses, campaigns and newest servants and Craft Essences; the events and summon banners from the same data are on Home's event board. Atlas's NA export has no login bonuses (none of its event types are login ones), so since 0.28.1 the block's login bonuses are NA's from NA's news, written into the page: `NA_LOGIN` in `src/app/47-announcements.js`, each with its dates, what it gives and a link; they show even when Atlas can't be reached. The test copies start with it switched off; `tests/test_17_live_na.py` turns it on against a local stand-in.

## Event pages and NA banners (0.22.0, tabs since 0.22.2)

Pressing an event on Home opens `#event/<id>` (or `#event/<id>/<tab>`), in `src/app/25-event-page.js`. The page shows one tab at a time:

- **Tabs from the wiki.** The Fate/Grand Order fandom wiki's NA event pages start with an `{{EventHeaderNA}}` (the event's exact name, start date, requirement) and a `<tabber>` of transcluded pages (`Main Info={{:Page/Main Info}} |-| Event Shop=…`). The page whose header names the event (or starts closest to it) is used; each tab's page is fetched through the MediaWiki API (`origin=*`) when it's opened, then the rest in the background. A page without a tabber is split at its headings.
- **Atlas Academy for the exact parts.** `/nice/NA/event/<id>`, its wars, the free quests' drops, `nice_item.json` and `basic_svt.json` give the shop (per currency, with totals), the calculator, the mission list and random missions by rank, free-quest drops, banners (with Simulate) and point rewards. Without the wiki, the tabs come from this data alone.
- **The filter.** Wiki HTML is rebuilt in an inert document keeping only plain tags, `href`/`src` that point to the web or the wiki's image servers, and `colspan`/`rowspan`. The wiki's phone-only copies (`.mobile-only`), hidden parts and tooltip buttons are left out; a tooltip's text becomes the `title`. The wiki's tabbers become this page's own tabs. Servant and Craft Essence icons carry their numbers (`S327A1Icon`, `CEIcon1498`), so links to servants, their Noble Phantasms and Craft Essences open Past Chaldea instead of the wiki.
- **Wiki-only events (0.24.0).** An event the wiki lists that NA's data doesn't have yet gets a negative id worked out from its wiki page's title (`wikiEvId`); its page is made from the wiki page and what Home's board read from its header, kept as `wev:<id>`.
- **Cache.** Events, wiki tabs and pages, item and servant names are kept in IndexedDB `fate-grand-index-cache` (separate from the pictures database); the 30 most recently opened events are kept.

The calculator uses each servant's ascension and skill materials (`ma`/`ms` in `atlas_data.js`, items in `ATLAS_MATS`). "Simulate" loads an NA banner into the summoning simulator (`src/app/26-banner-sim.js`). `tests/test_18_event_page.py` covers all of it against stand-ins; the wiki stand-in copies the markup of a real NA event page.

## Story page, Home board and the servant page's planner (0.24.0)

- **Story** (`src/app/32-story.js`, `#story`): main-story chapters (war ids 100–108, 201–204, 300–311, 400–404 in `STORY_CH`, each with a palette and a backdrop motif; title plates by `STORY_CAP`, since from war 303 on the `questboard_cap` number isn't the war's) are read at runtime from Atlas Academy's `/nice/NA/war/<id>` (main quests in the game's order by `priority`, a quest with none of its own placed after the section before it, side battles with a `chapterId` under 100 left out, labels from `chapterSubStr` with parts as 4-1, 4-2) and `/nice/NA/quest/<id>/<phase>` (enemies by wave; `deck: "shift"` entries are break bars, joined to their enemy by `enemyScript.shift`), made small and kept in `fate-grand-index-cache`. Where you stand is `localStorage` `spirit-origin-list:v1:story`. The next fight's advice uses the NP damage calculator. Away from the SERVANTPAGE, `#story-bg` draws the chapter's backdrop with CSS transforms and opacity only. `tests/test_28_story.py` uses the stand-ins in `tests/fixtures/story/`.
- **Home board** (`src/app/33-home-board.js`): with live updates on, the wiki's `Category:Current Event (US)` and `Category:Upcoming Event (US)` pages (their `{{EventHeaderNA}}`: image, dates and time zone, requirement, story, new servants), the App Store lookup for the NA (`1183802626`) and JP (`1015521325`) apps, and the wiki's `Template:GameUpdatesNA`; matched with NA's events and banners from "On NA now" (by start time and shared words, numbers included: 25M is 25 Million). Kept for 3 hours in `fate-grand-index-cache`.
- **SERVANTPAGE** (`src/app/29-planner.js`, `30-np-calc.js`): append levels, Servant Coins and a plan live on the servant (`appends`, `coins`, `ascAt`, `plan`). Costs come from `atlas_data.js` (`ma`/`ms`/`mp` materials, `qa`/`qs`/`qp` QP, `ATLAS_GRAIL`, `ATLAS_EXP`, `pm` for the class passives' damage buffs). What you have is shared with the Event calculator (`spirit-origin-list:v1:event`) and goes into backups. The calculator's buffs, supports and unticked skills are kept in `spirit-origin-list:v1:npcalc`; each skill's damage buffs come from `b` in `atlas_data.js` (kind, target, cards, ten values, condition; see `skill_buffs` in `tools/gen_atlas.py`). Servant Coins follow the + and −: a copy adds the summon's coins (`cn`), a Bond level 5/10/20, a Grail past Lv 100 takes 30, an append unlock 120.
- **Phones and touch** (`src/app/34-phone-tablet.js`): Modern (tiles, section shortcuts) and Compact (one-line rows, folded sections, `spirit-origin-list:v1:folds`) on phones; bigger targets and swiping between servants on touch screens.

## Icons, Craft Essence picks, the support picker and servant backdrops (0.25.0)

- **Icons** (`src/app/38-servant-icons.js`): `iconHTML` shows Atlas Academy's frameless face for the stage marked Icon (`Faces/f_<svt id><stage − 1>.png`, costumes `Faces/f_<costume id>0.png`), or per servant (`iconKind`) a framed icon, the portrait (`Servants/Status/<id>/status_servant_<1–3>.png`, costumes `_11`, `_12`…), the formation (`NarrowFigure/<id>/<id>@<n>.png`, stage 4 `<id>_2@0.png`), or the stage picture. These paths follow fixed patterns, checked against the whole NA export (the costume portrait's `_11`, `_12`… is the costume's limit count, in the same order as `cs`). A costume slot is matched to one of NA's costumes by `cosMap`: a pick on the servant page (`artCos`, `{slot: costume id or 0}`), else a picture from NA's data, else the closest NA name (`csn` in `atlas_data.js`, from `data/atlas/costumes.json`, which `tools/gen_atlas.py` reads: the export has no costume names; version numbers have to agree), else for an unnamed slot the next costume left. A named slot that matches nothing uses its own picture. Fan art (`art.fan`, `FAN_SLOT` in 00-core.js) is a tile after the costumes, stored like the stage pictures; marked Icon, it is the icon. A picture that fails falls back through `data-alt`.
- **Craft Essence picks** (`src/app/36-ce-suggest.js`): `ceFx` reads each Craft Essence's max limit break text for what always applies; `ceSuggest` scores them for the servant's NP (damage: card × ATK × NP Strength × the CE's ATK, times how much NP it starts with; support: NP at the start, NP Gain, NP each turn). Shown in Past Chaldea's servant window.
- **Support picker** (`src/app/35-support-picker.js`): the damage calculator's support buttons open a searchable window; the choice is still `npcalc.sup`.
- **Servant backdrops** (`src/app/37-servant-backdrops.js`, `OWN_BG`): a servant can have their own backdrop: the class canvas switches to one of its existing looks and a CSS layer (`#own-bg`) adds the rest. Sodom's Beast/Draco (No. 377), the Beast of Revelation, has a crimson and gold rose window turning behind her golden cup, falling stars and rose petals over the quiet motes canvas, and a crimson page tint (`page` in `OWN_BG`, through `extraAccOf`). Her art panel gets the cup as well (`OWN_SCENE`, a `.own-scene` layer `artHTML` puts between the scene canvas and the pictures).
- **Zoom**: `--ui-z` is `min(width / 1700, height / 840)`, so a window with the browser's bars on a 1080p screen (or 4K at 200%) is zoomed 1.125.

## The hosted site: app, accounts, sync and friends (0.26.0)

- **Hosting**: Cloudflare Pages serves `site/` and runs `functions/` (which hands every `/api/` request to `server/app.js`) with a D1 database bound as `DB`, an optional R2 bucket `PICS` for uploaded pictures (else they're kept in D1), and the secrets `PEPPER`, `DISCORD_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET`. The tables are made by the first request (`server/schema.js`). `docs/hosting.md` has the setup.
- **The app** (`src/app/40-app.js`, `src/site/sw.js`): the service worker keeps the page and icons, so the app opens offline; a new build has a new `sw.js` (named after the page's hash), and the page offers to reload into it. Install buttons appear where the browser allows it.
- **Accounts** (`41-account.js`, `server/auth.js`): the password is turned into a key in the browser (PBKDF2-SHA256, 600,000 rounds, salted with the email) and only the key is sent; the server keeps an HMAC of it with `PEPPER` (the free Workers plan's 10 ms of CPU can't hash passwords itself). No emails: recovery codes. Discord and Google with PKCE. Sessions in an HttpOnly, SameSite=Lax cookie; every change needs the `X-FGI` header.
- **Sync** (`42-sync.js`, `server/sync.js`): local-first. Saves through `localDb` and the remembered keys (`EXTRA_KEYS`) are noted in `spirit-origin-list:v1:sync` and sent; the server numbers every change, so pulling is "since N". Last save wins per entry; a change waiting to go out is never overwritten. Uploaded pictures go up once; other devices show them from `/api/pics/<owner>/<id>` and copy them into IndexedDB.
- **Friends** (`43-friends.js`, `server/friends.js`): friend codes, requests, roster visibility (`private`, `friends`, `link`), up to 10 supports per account, activity worked out by the server from what changed. A friend's roster or a shared link (`?roster=<token>`) replaces the lists on screen read-only (`FV`) until Back to yours. Friends' servants are `f:<friend>:<servant>` in the damage calculator and Versus.
- **Security**: `site/_headers` sets a Content-Security-Policy that runs only the page's two scripts (by their hashes, written by `tools/build.py`), since other people's names and notes now show on the page. Every answer, static or `/api/`, also says HTTPS only (HSTS, 0.26.1).
- **Crawlers and missing pages** (0.26.1): `site/robots.txt` lets search engines read the page but not `/api/`; an address that doesn't exist gets `site/404.html` (a real 404) instead of the page.
- **Friends' story and Guests** (0.26.1): a friend's roster comes with where they are in the story (`extras/story`, only the position), shown on their card, in the bar while you look, and on the Story page; any friend's servant can go into your own Guests with their levels; friends' supports count as "worth borrowing" on the Story page.

## The Servant Workshop and growth curves (0.27.0)

- **Growth** (`src/app/44-custom-servants.js`): HP and ATK climb from Lv 1 to the max level along one of six curves (the wiki's "Growth Curves": Linear, S, Reverse S, Semi S, Semi Reverse S, Semi Reverse S then Linear), and past the max level every servant with that max level shares the grail curve. `ATLAS_CURVES` has NA's numbers (per mille of the Lv 1 → max gain, Lv 1 to 120); a curve NA doesn't use at some max level is made by `synthCurve` from the same curve's shape plus that max level's grail part, under a key like `x:ss:1`. A servant NA doesn't have can keep `growth: {type, hp: [Lv 1, max], atk: [Lv 1, max]}` (Edit details → Growth), and `syncStats` then moves HP and ATK with its level the way it does for NA's servants.
- **Custom servants**: `custom: true` and `kit` (what the Workshop edits) on an ordinary servant entry, plus the usual fields made from the kit by `kitDerive` (skills, passives, deck, NP table, traits, growth). `atlasOf` never matches a custom servant to NA, whatever its name. `calcKitOf(s)` gives the damage calculator and the support pickers the NA record, or the same shape built from the kit (skill buffs, passives' card and Damage Plus bonuses, attribute).
- **Effects** (`FX`): 33 kinds plus "write your own", each with its targets, usual Lv 1 / Lv 10 values (a second pair for "yourself"), turns and times, how NA's text words it, and what it does to NP damage (the calculator's buff kinds). NA's skill and NP text is read back into effects for Remix (`naToFx`), and anything it can't read stays as written.
- **The Workshop** (`src/app/45-workshop.js`, `src/styles/28-workshop.css`): eight steps and a live card; parts flagged in `kit.auto` follow the class and rarity (`typicalOf`: NA's median stats, most used curve, deck, NP card, passives) until changed. The draft is `spirit-origin-list:v1:workshop`. Share codes are `FGI2.` + the kit as deflated base64url (`FGI1.` without deflate where `CompressionStream` is missing), cleaned by `wsClean` when opened.
- **Versus with NA**: picks like `na:<number>` are NA servants at max level, NP1 and skills at 10, built on the fly (`vnaGet`), never saved.

## Append skills for servants of your own (0.28.1)
- The Append skills section (`src/app/29-planner.js`) names an NA servant's five appends from Atlas Academy's data. A servant made in the Workshop isn't in that data, so it used to show five blank rows. Now `appendFor(s, a, i)` gives them NA's real ones: in NA's data four slots hold the same append on every servant (Extra Attack Boost, Load Magical Energy, Special Attack Boost, Skill Reload), so they come with the slot. Which slots are fixed and which vary is read from `ATLAS_S` (`AP_SLOT`), not written down.
- The third slot differs per servant (ATK Up or Critical Resistance Up against one class), so it's a list on their page: `select[data-ap-pick]`, grouped by kind, with Undo. The pick is kept on the servant as `appendPick` (the append's name, so it survives a reorder of the data), and nothing is guessed before it's picked. The levels are the same `appends` array as for any servant. Backups, the single-servant file, Edit details and the Workshop's save all keep it.
- The Planner still needs NA's material data, so a servant of your own has no costs there (it says so, as before).

## Battle (0.50.0-beta)
- The engine (`src/app/49a-battle-engine.js`, all `bt`/`BT_`): `btBattle({party, waves}, seed)` plays a whole fight with a seeded random number (`btRng`, so a seed repeats its fight) and returns every step (`events`, each with a snapshot `s` of everyone's HP, NP, charge and buffs), the result (`win`, `lose`, `time` after 40 turns) and each unit's totals. Damage follows the game's formula (class and attribute affinity, card and chain bonuses, crits, buffs and debuffs, Overcharge); NP gain and hit counts use class defaults (the data has no per-servant ones).
- Fighters: `btFromServant` (yours: level, skill and NP levels, Fou, CE, Append 2 and 3; custom servants from `kitNow`), `btFromNA` (NA's at max level, skills 10), `btFromMade`, `btAsFoe`, `btFromQuest`. NA's skill and NP lines are read into effects by `BT_READ` (`btClauses` splits "&" lines; "Apply a state …" is left alone).
- `window.__fgiBattle` exposes the engine for the tests (frozen; no access to the roster beyond a copy).
- The page (`src/app/49b-battle-ui.js`, `src/styles/33-battle.css`): the setup is `spirit-origin-list:v1:battle`. ## 0.53.0-beta: the 3D background (vanta.js)

- `59-bg3d.js`, `38-bg3d.css`. One WebGL canvas (`#bg3d`, right after `.page-bg`) drawn by [vanta.js](https://www.vantajs.com/) on three.js r134. The libraries are in `src/vendor/` (MIT, licences beside them) and are put into the page by `@@include:vendor/...@@` inside `bg3dLoad()`, so they only run when a 3D background is wanted.
- `bg3dWant()` says what should be up: on the usual pages the picked effect (`spirit-origin-list:v1:bg3d-fx`, the globe when absent) in the page's `--g1..3`; with a story scene, `bg3dActKind(act)` picks from the scene's weather and parts (an act can name one with `v`). A sea (`waves` on a scene with a `flat` row) puts the camera just above the water with the far edge of the mesh on the scene's waterline (`bg3dSea`). `bg3dSync()` starts, recolours or swaps the effect; `html.bg3d-on / .bg3d-story / .bg3d-sea` switch off what the picture replaces (the summoning circle, a scene's drawn sky, a sea's drawn water: `.sc-ff` and `.sc-flat`; the canvas is behind every sheet, so sheets beyond the water are cut at the waterline, `.sc-far` and `--cutb`). Net and globe lines are added to the picture under the canvas in the dark theme (`bg3dGlow`); clouds over a scene are turned upside down (`.bg3d.flip`), since vanta shows them from above.
- Cost: `BG3D_PX` megapixels for each effect (`bg3d-q` = `full` gives four times as many); `bg3dDrive` replaces vanta's loop with one at `ambFps()` that stops while `resting`, `idleRest`, the tab is hidden, the summoning is up or a phone's sheet covers the page. Reduced motion, no WebGL or a lost context fall back to the drawn background (`bg3dDead` says why on Settings). `spirit-origin-list:v1:bg3d` = `off` switches it off. A browser driven by a test tool (`navigator.webdriver`) starts without it unless that key is `on`, because such machines draw WebGL on the processor.
- The light/dark switch: `setTheme` sends an `fgi-theme` event once the theme has changed. The story scene and a servant's backdrop redraw on it (they used to redraw on the click, before the view transition had switched the theme).
- **Black and cream** (`39-palette.css`, `60-palette.js`): the page's colours since 0.53.0, in both looks; the navy of 0.50 to 0.52 is gone. `39-palette.css` holds the colour variables (`html:root`): true black in dark mode, cream white in light mode, gold as the accent. `paintPage` is wrapped so the page's own `--g1..3` stay black in dark mode and are cream with a tenth of the servant's or chapter's colour in light mode. `tests/test_49_palette.py`.
- `window.__fgi3d` has `state`, `want`, `kindOf`, `sync`. `tests/test_48_bg3d.py` launches Chromium with SwiftShader for WebGL.

## Your data

Your roster is stored in your browser: `localStorage` key `spirit-origin-list:v1`, pictures in IndexedDB `spirit-origin-list-images`. These names never change, so existing saves keep working with every new version. Signed in on the hosted site, the same data is also kept in your account (0.26.0); the file opened from your computer never talks to a server.

Importing a backup or a spreadsheet replaces entries that share an ID, so the page keeps a copy of the list in memory first and offers **Undo import** until you press Keep it, import again or reload (`importSnap` / `importUndo` in `src/app/07-core-rendering-forms-events.js`). If a save fails because the browser's storage is full, `#save-warn` stays above the page until a save works again. In Chrome, every page opened from a file shares one storage space (`file://`), so other local pages count toward the same limit.
